# M0 deploy and phone install

Site URL: https://nobody174.github.io/drum-bass/ (Vite `base` is `/drum-bass/`).

## One-time setup

1. Push the repo to `nobody174/drum-bass` on GitHub (branch `main`).
2. GitHub repo > Settings > Pages > Build and deployment > Source: **GitHub Actions**.
3. Push to `main` (or run the "Deploy to GitHub Pages" workflow from the Actions tab). The workflow runs `npm ci`, `npm run build` (typecheck + Vite build), `npm test`, then publishes `dist/`.
4. First deploy takes about 1-2 minutes. The URL is shown in the workflow run's `deploy` job and under Settings > Pages.

## Install on Android (Chrome)

1. Open https://nobody174.github.io/drum-bass/ in Chrome and let it load once (this fills the offline cache).
2. Chrome menu (three dots) > **Install app** (or **Add to Home screen** > Install). Launch it from the home screen icon; it opens standalone without the address bar.
3. Turn the phone sideways: the app uses `orientation: any`, so it is not locked.

## Updating

- Deploy: push to `main`. Nothing else.
- The service worker uses `registerType: 'autoUpdate'`: the new version downloads in the background and activates on the next launch/reload. Close the app fully (swipe away from recents) and reopen it, possibly twice, to see changes.
- Force a refresh: Chrome > Settings > Site settings > All sites > nobody174.github.io > **Clear & reset** (or in an inspected tab: DevTools > Application > Service Workers > Unregister, then Clear storage). Uninstalling and reinstalling the PWA also works. Note this clears IndexedDB (kits, songs) for the origin.

## Inspecting on the phone

- **Remote debugging (works with HTTPS, so MIDI works):** enable Developer options + USB debugging on the phone, connect via USB, open `chrome://inspect/#devices` on the PC Chrome, then Inspect the app/tab. Console, Network, Application > Service Workers/Manifest are all available.
- **Dev server on the PC:** `npm run dev` (it already uses `--host`), then open `http://<PC-LAN-IP>:5173/drum-bass/` on the phone (same Wi-Fi). Good for UI/touch/layout iteration with hot reload.
  - Caveat: **Web MIDI requires a secure context (HTTPS or `localhost`)**. Plain `http://192.168.x.x` does NOT get MIDI access, and service worker/install also need a secure context. Use LAN http for UI testing only. For MIDI tests use the deployed HTTPS site, or `chrome://inspect` port forwarding (Port forwarding: `localhost:5173` -> phone then opens `http://localhost:5173/drum-bass/` as a secure context).
- Local production check: `npm run build && npm run preview`, then open `http://localhost:4173/drum-bass/`.

## Phone test checklist (M0, no drum kit needed)

- [ ] Site loads over HTTPS; no certificate or blank-page errors.
- [ ] "Install app" is offered; install succeeds; home screen icon looks right (dark, red-orange drum with bolt, not cropped badly).
- [ ] Opens standalone (no browser bar), splash/theme colour is dark.
- [ ] Rotates freely; landscape layout is usable, nothing overflows or is cut off by notch/gesture bars.
- [ ] Fonts render (Bebas Neue / Oswald headings, Inter body).
- [ ] On-screen pads: every pad responds to touch, multi-touch works (two fingers at once), touch targets feel at least 48 px, no accidental scroll/zoom/text selection.
- [ ] MIDI monitor screen opens; permission prompt appears when requesting MIDI; with no device it shows a sensible "no devices" state instead of crashing.
- [ ] Airplane mode: close and reopen the installed app; it still loads fully (offline).
- [ ] Push a trivial change to `main`, wait for the deploy, relaunch the app twice: the change appears.
- [ ] Note any problems (device model, Chrome version, screenshots) in `docs/`.

## Known local quirks

- On the dev PC, Windows Application Control blocks `rollup.win32-x64-msvc.node`, which `vite-plugin-pwa` (workbox-build) needs to bundle `sw.js`. `vite build` then emits everything except `sw.js`. The GitHub Actions Linux runner is not affected, so verify the service worker on the deployed site (DevTools > Application > Service Workers, scope `/drum-bass/`).
- Vitest from Git Bash on Windows can fail with "Cannot read properties of undefined (reading 'config')" because of lower-case drive-letter paths; run `npm test` from PowerShell/cmd.
- Icons are generated by `node scripts/generate-icons.mjs` (no dependencies); re-run it after changing the design and commit the PNGs in `public/`.
